# Superdesign 视觉与动效改造方案

日期：2026-10-28  
状态：调研建议，待确认范围；不是已批准的开发 spec。

## 目标与建议方向

本方案以当前仓库 YobboyFileServer 为对象。建议保留现有功能布局、主题配色和表面样式，将 Superdesign 中的局部交互应用到工作区入口、历史记录与操作状态。

设计方向：清晰的工具工作台，辅以少量有意义的动效。入口负责识别工具，历史记录负责解释先后关系，状态反馈负责说明程序正在做什么。

本轮只交付调研和方案，没有修改业务代码、安装前端依赖或调整运行数据。以下参数和范围均为建议，尚未经过目标网站的视觉验收。

## 调研依据与已知限制

- 第一方参考：Superdesign 用户指定的 `timeline-vertical-journey`、库内组件说明及可取得的示例源码。组件来源、行为和依赖见 [研究记录](research/superdesign-reference-notes-2026-10-28.md)。
- 仓库主要前端是 Flask/Jinja 模板、Bootstrap、原生 CSS/JavaScript；局部模块另有自己的前端工具链。方案针对主站，不要求迁移框架。
- `templates/choice.html` 已有六个工作区入口；`static/css/choice.css` 的悬停效果是卡片上移 3px、阴影和箭头位移。
- `templates/todo_v2.html` 的 `historyModal` 用四列表格显示改动和评论；`static/js/todo_v2.js` 已合并两类记录、按时间倒序排列，并提供三类筛选。
- 现有 `todo_v2_timeline.*` 展示任务起止跨度，属于横向排期视图。Vertical Journey 更适合历史记录，不作为该视图的直接替代。
- `templates/index.html` 的 `gitHistoryList` 目前使用普通列表展示提交哈希、摘要、作者、时间和改动数量。
- `static/js/git_operations.js` 已有处理中、成功、失败三类反馈；`static/css/local_ai.css` 已有待确认红色循环脉冲与忙碌缩放动画。
- `templates/_theme_bootstrap.html` 和 `static/css/themes.css` 已提供主题预加载与变量；工作区菜单提供六种配色和纯色、玻璃、粘土三种表面样式。应优先适配这些变量。
- 现场浏览到本地打包应用的登录页，未进入受保护业务页；随后本地服务拒绝连接。因此业务页现状以当前源码为依据，尚未核对打包程序与工作区是否一致。
- Superdesign 库目录和组件说明可读，但浏览器中的示例 iframe 持续加载。本轮不声称已经实测这些示例的动画流畅度。

| P1 | AI 面板、Git 操作反馈 | Timeline: Status Tracker、Radiant Prompt Input | 将已有状态表现为紧凑状态条/节点，统一忙碌、待确认、成功与失败反馈；AI 输入框聚焦时短暂强调边缘，循环闪烁收敛为短促提示 | 操作状态更明确；只显示已有事件能证明的阶段，没有真实百分比时显示不定进度 |

推荐首批只落地 P1 三处。P2 在首批效果验收后复用，P3 暂作候选。

## 关键交互草案

### 任务历史

节点包含：时间、修改/评论标记和完整正文。修改节点保留字段名称、旧值与新值；长评论自然换行，空记录显示明确空态。进入弹窗即可读到首屏内容，动画不阻塞阅读或操作。

所有连接线表示事件关系。若保留随阅读出现的线段填充，应说明其仅表示已读到的位置；不得据此推断任务完成比例。筛选后按当前可见记录重新排列节点，不保留无对应内容的空连接。

现有横向工期时间轴、汇报表和导出格式继续使用各自的信息结构。本轮不增加新的任务类型、里程碑数据或状态字段。

### 入口卡片

优先给文件浏览器入口增加有辨识度的文件夹开合；其他入口通过现有图标和统一的轻反馈保持一致。点击区域始终覆盖整张卡片，文字、键盘焦点和入口位置不因动画移动到难以操作的位置。

触屏直接进入工作区，不把悬停作为必要步骤。动画不改变页面布局；首屏出现效果最多作用于这六个入口，返回页面或切换主题时避免反复播放。

### 操作状态

Git 已有三态可以直接改进外观。AI 的具体阶段应以现有事件接口核对结果为准；若只有忙碌/完成/失败，就只展示这些状态。后端新增阶段事件属于独立范围，不能为实现一个视觉样例顺带扩展。

失败状态持久显示原因和现有可用操作；成功提示短促结束；待确认始终可辨认，不以持续闪烁作为唯一线索。停止生成、确认变更和重复提交保护保持原有语义。

## 统一动效规则（建议值）

- 按钮、悬停反馈：120–180ms；面板和弹窗：180–240ms；事件首次出现：240–320ms。
- 卡片或事件的位移控制在约 4–8px；分批间隔约 30–40ms，并限制总等待时间。高频刷新不整页重播。
- 主要使用透明度和位移变化；颜色、边框等沿用现有 `--t-*` 变量。保留当前字体与本地图标，不增加在线字体请求。
- 只有进行中的任务可以保留小范围活动指示；停止、完成或面板隐藏后结束动画。
- `prefers-reduced-motion` 下直接呈现最终可读状态。不能把元素停在透明、移出屏幕或未完成的中间状态。
- 文字与焦点清晰可见；状态同时使用文案或图标，不只依靠颜色。
- 工作页面暂不采用鼠标尾迹、全屏粒子、持续大面积流光、强视差、滚动锁定或长时间逐字出现。

## 落地方式

以原生 CSS/JavaScript 复现选定的交互思路，继续使用本地静态资源。部分参考有 React 或动画库包装，不把它们作为引入整套运行时的理由。

共用内容仅包含动效时长、缓动和减弱动态规则；事件线及具体页面行为放在独立小文件中。已有较大的 `todo_v2.js` 与 `index.html` 尽量只增加调用入口，避免把多个无关效果堆在一起。

按页面接入和验收，便于单独撤回一个效果。第一批不更改接口、数据库、业务流程或全站导航。

## 实施顺序与验收

1. **确认范围并形成正式 spec。** 确认首批页面、动效强度及公共测试边界；把本方案中的建议参数收敛为验收项。
2. **小样对比。** 在既有主题预览页或独立评审样例里展示三种 P1 效果，比较浅色/深色、纯色/玻璃/粘土及减弱动态状态。此阶段不改业务页面。
3. **首批接入。** 依次接入任务历史、入口卡片、操作反馈，每处独立验证。
4. **回归与扩展判断。** 对照 spec 验收，完成规范与符合度审查，更新文档；通过后再决定是否推进 Git 历史和弹窗。

拟定的公共验收边界：

- 从真实入口进入六个工作区，鼠标、键盘和触屏均可操作，焦点不丢失。
- 打开任务历史并切换三类筛选，排序、条数、旧值/新值、长中文评论和空态正确；至少覆盖百条历史记录。
- 观察操作开始、成功、失败、待确认和停止后的可见状态，不出现虚假完成、重复提交或持续残留动画。
- 在 375、768、1440px 宽度检查布局；六种配色与三种表面样式做视觉抽查，首批重点验收浅色、深色及低动态组合。
- 无外部网络时新增效果可用；页面切换不新增主题闪烁；长列表和串口收发期间不新增明显卡顿。
- `prefers-reduced-motion` 下内容完整，状态明确，操作不依赖动效结束。

正式 spec 中再固化浏览器用例和命令。仓库目前的 `e2e/example.spec.js` 不能当作本次验收覆盖。实现时增加针对真实公共行为的必要回归，并运行相关测试和完整现有测试；本轮没有执行或宣称通过这些检查。
